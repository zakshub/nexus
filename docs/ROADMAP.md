## Phase 0: Discovery and validation

**Goal:** Decide what should be built and prove the integration boundaries.

Deliverables:
- Verified environment inventory
- Prioritized user workflows
- Android and Termux integration feasibility report
- Security threat and risk assessment
- Architecture recommendation with alternatives
- Initial data model
- Revised effort estimates
- Phase 1 scope and acceptance criteria

Exit criteria:
- Major platform constraints are documented.
- MVP scope is narrow and testable.
- Architecture recommendation is evidence based.
- High risk assumptions have a validation plan.
- Owner approves Phase 1.

## Delivery rules

- Each phase is broken into milestones and tasks.
- Every task has an outcome and acceptance criteria.
- Estimates are provisional until Phase 0.
- Update completion percentages using evidence, not intuition.
- Do not begin a later phase while its dependency or approval gate is unresolved.
- Reassess scope after each milestone.
